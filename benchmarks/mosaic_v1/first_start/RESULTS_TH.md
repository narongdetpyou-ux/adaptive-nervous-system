# ผลการให้สิทธิ์เริ่มงานหนึ่งครั้ง

**ข้อสรุป: คงตัวจัดคิวเดิม `size_600_0.03`** งานใหญ่ได้เริ่มจัดแนวเร็วขึ้นมาก แต่ได้ภาพสุดท้ายช้าเท่าเดิม และ P99 ของทุกคำขอสูงขึ้น จึงไม่ผ่านเงื่อนไขการเปลี่ยนตัวจัดคิวที่ประกาศไว้ใน [plan.json](plan.json) ทั้งสองวิธียังผ่านเกณฑ์ Mosaic Queue v1 ครบ 22 ข้อ หลักฐานรันจริงทั้งสามวิธีและการตรวจภาพครบแล้ว

| คิวจำลองหลัก 24,576 คำขอ | รุ่นเดิม | ให้สิทธิ์เริ่มหนึ่งครั้ง | เปลี่ยนไป |
|---|---:|---:|---:|
| เวลารอก่อนเริ่มจัดแนวของงานใหญ่ที่ P99 | 328.68 วินาที | 8.86 วินาที | −97.3% |
| เวลารอรับภาพสุดท้ายของงานใหญ่ที่ P99 | 350.36 วินาที | 350.76 วินาที | +0.1% |
| เวลารอรับภาพสุดท้ายของทุกคำขอที่ P99 | 168.41 วินาที | 172.19 วินาที | +2.2% |
| เวลาเฉลี่ยของทุกคำขอ | 16.04 วินาที | 16.20 วินาที | +1.0% |
| P95 ของทุกคำขอ | 60.16 วินาที | 60.98 วินาที | +1.4% |

P99 คือเวลาที่คำขอ 99% เสร็จภายในค่านั้น ค่ายิ่งต่ำยิ่งดี งานใหญ่ในชุดนี้มี 6,179 คำขอ กติกาที่ทดลองคือคำขอที่มีอย่างน้อย 4 ภาพและยังไม่เคยเริ่ม เมื่อรอครบ 8 วินาทีจะได้จัดแนวหนึ่งเฟรมก่อน จากนั้นใช้ลำดับคิวเดิม ในคิวจำลองหลักกติกาให้สิทธิ์ 3,526 ครั้ง และเปลี่ยนงานที่จะส่งต่อไปจริง 3,523 ครั้ง

**เวลารอไปอยู่ที่ไหน** เมื่อตามคำขอจากชุดพัฒนา 21 รายการที่ช้าที่สุดในกลุ่มงานใหญ่ของรุ่นเดิม ระยะเฉลี่ยระหว่างเริ่มเฟรมแรกกับเฟรมที่สองเพิ่มจาก 10.64 เป็น 356.60 วินาที ผู้ใช้ต้องรอหลายเฟรมเพื่อให้โมเสกภาพแรกเสร็จ การเริ่มเฟรมแรกเร็วขึ้นจึงไม่ได้ทำให้ได้ภาพเร็วขึ้น [ดูเวลาทั้งสี่ช่วง](diagnosis.json)

## เงื่อนไขการเปลี่ยนตัวจัดคิวที่ประกาศไว้

| เงื่อนไข | ผล |
|---|---|
| P99 ของทุกคำขอต้องลดลง | ไม่ผ่าน: 168.41 → 172.19 วินาที |
| P99 เวลารอเริ่มของงานใหญ่ต้องลดลง | ผ่าน: 328.68 → 8.86 วินาที |
| เวลาเฉลี่ยและ P95 สูงขึ้นไม่เกิน 10% | ผ่าน: +1.0% และ +1.4% |
| ผ่านเกณฑ์ Mosaic Queue v1 ครบ 22 ข้อ | ผ่าน: ทั้งสองวิธีได้ 22/22 |

ต้องผ่านทุกข้อพร้อมกัน ผลจากโปรแกรมตรวจจึงเป็น `retain_incumbent`

## รันจริง 48 คำขอบน CPU 4 ตัว

| | ทำทีละคำขอ (fixed4) | รุ่นเดิม | ให้สิทธิ์เริ่มหนึ่งครั้ง |
|---|---:|---:|---:|
| เวลาเฉลี่ย | 7.42 วินาที | 2.92 วินาที | 2.94 วินาที |
| P95 | 18.40 วินาที | 8.15 วินาที | 7.90 วินาที |
| P99 | 21.04 วินาที | 10.09 วินาที | 10.20 วินาที |
| ภาพสุดท้ายของงานใหญ่ 10 คำขอที่ P99 | 19.45 วินาที | 10.45 วินาที | 10.78 วินาที |
| ภาพและแผนที่พื้นที่ที่ hash ตรงกับภาพอ้างอิง | 120/120 | 120/120 | 120/120 |

ในการรันจริงกติกาไม่ได้ทำงานเลย คือให้สิทธิ์ 0 ครั้ง เพราะงานใหญ่ทุกคำขอได้เริ่มจัดแนวก่อนครบ 8 วินาที (นานที่สุด 2.82 วินาที) ลำดับงานจึงเหมือนรุ่นเดิม ตัวเลขที่ต่างกันเล็กน้อยเป็นความผันผวนระหว่างการรันแต่ละรอบ เช่น fixed4 บนเครื่องเดียวกันวัดได้ 7.42 วินาทีในรอบนี้ และ 7.58 วินาทีใน[การรันซ้ำ Mosaic Queue v1](../reproductions/20261125/README_TH.md) รันจริงรอบนี้จึงยืนยันการประมวลผลภาพและเกณฑ์เวลา แต่ไม่ได้วัดผลของกติกา ตัวเลขมาจากการรันรอบเดียวต่อวิธี บนเครื่องที่เร็วกว่าเครื่องที่บันทึกผล Mosaic Queue v1 เดิม ทั้งสามวิธีรันต่อกันบน CPU 0–3 ชุดเดียวกัน
