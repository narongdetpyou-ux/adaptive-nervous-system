# V5 · ผลชุดพัฒนาและชุดคัดเลือก

**ผลตามกติกาที่ประกาศไว้: เลือก V5 Full (`v5_full`)** V5 Full แก้จุดที่ V4 แพ้ Capacity Balance ในระบบที่บัฟเฟอร์จำกัดได้แล้ว ทั้งงานตกหล่น งานค้างปลายช่วง และ tail AUC แต่ในระบบที่บัฟเฟอร์ไม่จำกัด V5 Full ยังแพ้ Balance ด้านงานค้างปลายช่วงและ tail AUC และมีความเสี่ยงสูงกว่า V4 Hybrid เล็กน้อยในบางสภาพ

ผลนี้เป็นการคัดเลือกจากข้อมูลชุดพัฒนาเท่านั้น สถานะการเลื่อนรุ่น V5 ยังเป็น **NOT EVALUATED** เพราะยังไม่ได้เปิดชุดยืนยัน (6000–6063) และชุด OOD (8000–8063)

## ทำอะไรไปบ้าง

- **ชุดพัฒนา:** seed 2000–2007 และ 4000–4063 (792 กรณีต่อสภาพการทำงาน รวม 85,536 episode) รันครบทุกแบบ ใช้รายงานเปรียบเทียบเท่านั้น

## ความไวต่อข้อมูลที่ใช้จัดอันดับ

การจัดอันดับเหล่านี้ไม่เปลี่ยนผลการคัดเลือก

| ข้อมูล | อันดับ 1 | อันดับ 2 | หมายเหตุ |
|---|---|---|---|
| ชุดคัดเลือก (ใช้ตัดสิน) | v5_full · 6/3 · 39,999 | v5_no_regime · 6/3 · 40,033 | |
| ชุดพัฒนา | v5_no_regime · 9/1 · 44,945 | v5_full · 9/1 · 44,949 | ต่างกันไม่ถึง 5 หน่วย |
| ชุดพัฒนาและชุดคัดเลือกรวมกัน | v5_full · 6/1 · 44,049 | v5_no_regime · 6/1 · 44,052 | |

ตัวเลขในตารางคือจำนวนข้อที่แพ้ด้านงานตกหล่น/ปลายช่วง / จำนวนข้อที่แพ้ด้านความเสี่ยง · งานตกหล่นเฉลี่ยใน delayed_noisy

- **V5 Full กับ v5_no_regime แทบเท่ากันทุกชุดข้อมูล** แปลว่าคุณสมบัติตรวจจับการเปลี่ยนสภาวะ (regime) แทบไม่เปลี่ยนผลเลย
- **ชุดพัฒนา:** V5 Full แพ้ 9 ข้อ คือ 6 ข้อเดียวกับชุดคัดเลือก และอีก 3 ข้อในสภาพ startup ส่วนความเสี่ยงแพ้ V4 Hybrid ข้อเดียว (legacy_instant)
- **V4 Hybrid แพ้ Balance 15 ข้อทั้งสองชุด** สอดคล้องกับ 15 คู่ที่ V4 เคยแพ้ในชุดยืนยันของ v0.4

## การตรวจ

- **ผลของ seed 4000–4063 ตรงกับค่าที่บันทึกไว้:** ตรวจกรณีที่ V4 ใช้เป็นชุดยืนยันมาก่อน (704 กรณีต่อสภาพการทำงาน) กับ `v4_results/validation/decision.json`
  - ค่าที่ตรวจ: ค่าเฉลี่ยของ V4 Hybrid, V2 และ Balance และความเสี่ยงของ V4 Hybrid, V3, V2 และ Balance
  - ต่างจากค่าที่บันทึกไว้มากที่สุด 2.6×10⁻⁹ ซึ่งอยู่ในเกณฑ์ 10⁻⁶
- **ผลซ้ำได้:** รัน seed 5000 ซ้ำแล้วได้ไฟล์ตรงกันทุกไบต์ และ SHA-256 ของไฟล์ผลทุก seed (88 ไฟล์) อยู่ในไฟล์สรุป
- **ตัวสร้างกรณีถูกต้อง:** ให้กรณีเหมือนตัวสร้างที่ถูกตรึงทุกค่าทั้ง seed 2000–2007 และ 4000–4063
- **งานย่อยตรงกับตัวรันเดิม:** ให้ผลตรงกับตัวรันชุดพัฒนาเดิม
- **ไม่ได้แตะชุดที่ปิดไว้:** ไม่ได้สร้างหรือประเมิน seed ใดในช่วง 6000–6063 และ 8000–8063 โค้ดปฏิเสธช่วงเหล่านี้
- ผลรวมอยู่ใน [v5_results/selection/summary.json](v5_results/selection/summary.json) และ [v5_results/development_grid/summary.json](v5_results/development_grid/summary.json)

## สัญญาณล่วงหน้าก่อนชุดยืนยัน

- **เกณฑ์เลื่อนรุ่น:** ต้องผ่านทุกข้อ คือด้านงานตกหล่นและปลายช่วง 36/36 และด้านความเสี่ยง 24/24
- **บนชุดคัดเลือก:** V5 Full แพ้ 6 + 3 ข้อ
- **ถ้าชุดยืนยันออกมาคล้ายกัน:** V5 Full จะไม่ผ่าน โดยเฉพาะงานค้างปลายช่วงและ tail AUC ในระบบที่บัฟเฟอร์ไม่จำกัด ซึ่งทั้ง V4 และ V5 แพ้ Balance ต่อเนื่อง
- **ข้อจำกัดของสัญญาณนี้:** เป็นการประมาณจากข้อมูลชุดพัฒนา ยังไม่ใช่ผลตัดสิน

## ขั้นถัดไปตาม V5_DESIGN.md

1. ทำ adapter สำหรับ OOD 6 ครอบครัว
2. ทำ evaluator และผู้ตรวจอิสระ
3. ตรึงทุกอย่าง แล้วรันซ้ำเพื่อยืนยัน
4. เปิดชุดยืนยันและชุด OOD

ถ้าจะออกแบบแก้จุดอ่อนในระบบที่บัฟเฟอร์ไม่จำกัดก่อน ต้องประกาศตัวเลือกใหม่ และใช้ seed ชุดคัดเลือกชุดใหม่ เพราะชุด 5000–5015 ถูกใช้ตัดสินไปแล้ว

## รันซ้ำ

ใช้ Python 3.12.14 และ NumPy 2.3.5 รันจากโฟลเดอร์ `simulation/` ใช้เวลาประมาณ 3.3 ชั่วโมงบน CPU 4 ตัว

```bash
OPENBLAS_NUM_THREADS=1 python v5_grid.py run --split selection --workers 4
OPENBLAS_NUM_THREADS=1 python v5_grid.py run --split development --workers 4
python v5_grid.py summarize
```

ไฟล์ผลรายกรณีอยู่ที่ `local_runs/v5_grid/<split>/episodes-<seed>.csv` (ไม่ได้ commit) ถ้าการรันถูกขัดจังหวะ สั่งใหม่ด้วยคำสั่งเดิมได้เลย ตัวรันจะข้าม seed ที่เสร็จแล้ว
